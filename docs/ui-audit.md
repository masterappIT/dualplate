# 介面與操作流程檢查（2026-10-16）

檢查方式：負責人在瀏覽器逐頁操作管理端（1366px）與客戶端（手機寬度），以「代辦公司每天怎樣用、李先生怎樣用」為標準。

## 一、管理端的根本問題：結構還是「代辦新牌」的舊思路

| # | 問題 | 對日常運作的影響 |
|---|---|---|
| A1 | **兩個首頁**：「管理總覽」管到期、「案件工作台」管案件，各自有提醒數字 | 每天早上要看兩頁，還要自己合併判斷先做甚麼 |
| A2 | **兩套到期系統並存**：舊的「牌證」（工作台的「牌證日期提醒」）和新的「到期項目」互不相通 | 同一個日期可能要錄兩次，兩邊數字對不上 |
| A3 | **客戶資料四散**：客戶頁只有牌照、車輛、案件；公司在「公司與指標」，要重新選客戶；規則在另一頁 | 處理李先生的事要在 3–4 頁之間跳來跳去，沒有「一個客戶一頁看全」 |
| A4 | **待錄入只能逐個點進去補**：總覽有 6 項「待錄入」，但列表上不能直接填日期 | 12 個牌、每牌 3–5 個日期，逐頁點擊錄入非常慢 |
| A5 | **沒有批量錄入**：沒有 Excel 匯入，也沒有表格式批量編輯 | 新客戶一次交 12 個牌時，建檔要花大半天 |
| A6 | **案件仍是舊的十類官方節點**：每個節點有 6 個狀態下拉，滿屏官方來源；沒有負責人、截止日、需要客戶提供的文件清單 | 員工不知道誰在跟、何時要完成；客戶要交甚麼文件沒地方記錄 |
| A7 | **兩地牌列表欄位不夠用**：只有車牌、客戶、路線、上牌、使用狀態 | 看不到持牌公司、下一個到期、出租狀況，要逐個點進去 |
| A8 | **沒有員工與分工**：只有管理員一種角色 | 人手增加後無法分配客戶、無法追蹤誰負責 |
| A9 | **文字與品牌還是舊定位**：「跨境車牌代辦 OPERATIONS HUB」「以官方流程為依據」、每頁英文小標、側欄兩個相同圖示 | 看起來像通用代辦系統，不像「車牌管家」 |

## 二、客戶端仍欠缺的

| # | 問題 | 影響 |
|---|---|---|
| C1 | 只能用電郵加密碼登入 | 客戶習慣微信一鍵登入或手機驗證碼；電郵密碼容易忘 |
| C2 | 「需要你處理」只來自案件節點，客戶**不能在手機上傳文件** | 要客戶交行駛證、保險單時，仍要靠微信來回傳 |
| C3 | 沒有「你的顧問」聯絡方式 | 客戶有問題不知道找誰 |
| C4 | 沒有租金和報稅資訊 | 李先生最關心的收入和公司合規看不到（對應排隊中的出租、報帳模組） |
| C5 | 沒有任何推送提醒 | 到期提醒只能等客戶自己打開 App 才看到 |

## 三、建議的管理端新結構

```
今日工作      ← 合併總覽和工作台：到期待辦、進行中業務、待錄入資料、本月租金和報稅，列表上可直接操作
客戶          ← 一個客戶一頁看全：概覽｜公司組｜牌照｜車輛與司機｜業務｜租金｜報稅｜文件
牌照          ← 全部牌照總表（持牌公司、下一個到期、出租、狀態），可批量填日期、Excel 匯入
業務          ← 工單：負責人、截止日、清單、需要客戶提供的文件；列表或看板
租金 / 報稅   ← 排隊中的兩個模組
設定          ← 規則、官方來源、會計公司、員工與權限、合約範本
```

- 刪除舊「牌證」系統，全部日期只用一套到期項目
- 「待錄入」在今日工作和牌照總表都能直接填，不用跳頁
- 工單取代舊的十類官方節點：按業務類型套用可編輯的清單範本，最後一步固定「海關及邊檢備案」

## 四、建議的客戶端補強

- 微信一鍵登入（小程序官方能力，免費）＋手機號碼登入
- 客戶可在「需要你處理」裡直接拍照上傳文件，顧問核對後打勾
- 「我的」頁加入顧問姓名、電話、微信
- 出租、報稅模組完成後接上首頁和牌照詳情
- 推送：微信訂閱消息（官方免費）提醒到期和待辦

## 五、建議次序

1. 管理端拆分（已排隊，不改畫面）——之後改結構才快
2. **管理端結構重整**：今日工作、客戶一頁看全、牌照總表與批量錄入、刪除舊牌證系統
3. **工單改版**：取代舊案件節點，加入負責人、截止日、文件清單、客戶上傳
4. 出租合約、報帳報稅（已有任務說明）
5. 客戶端登入方式、顧問聯絡、推送
