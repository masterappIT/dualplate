## 乙、按客戶分類（管理者 2026-10-17 同意）

### 背景

每月報帳的工作有兩個方向：**向客戶收票據是按客戶的**（例如一位客戶一次交齊名下 11 間公司的票據），**交給會計公司是按會計公司的**。現在頁面只能按會計公司篩選，客戶名稱只以小字顯示，要在全部公司裏逐行找。參照 v1 計劃第五節的 TaxDome／Karbon：同一張工作清單可按客戶或負責單位篩選，客戶頁顯示該客戶的工作進度。

### 1. 本月工作分頁：加「客戶」篩選

- 放在現有「會計公司」篩選旁邊，兩個可同時使用（交集）。沿用 `Select`，開 `filterable`（客戶多時要能搜尋）。第一項「全部客戶」。
- 選項只列**有報帳期數**的客戶，按名稱排序。
- 清單**仍按緊急程度排序**，不要改成按客戶排序或分組。
- 篩選後勾選、全選、批量操作照常可用，只作用於篩選後看得到的期數。切換篩選時清掉已選但已不在清單內的項目（現有 `selected` 的做法）。
- 統計卡（需處理、已逾期、缺回執、本月已申報）跟着篩選結果計算，和現在按會計公司篩選的做法一致。
- 網址帶 `?customer=<客戶 ID>` 時，打開頁面自動選好該客戶（供第 3 點的連結使用）；ID 不存在或不在選項內時當作「全部客戶」，不報錯。

### 2. 歷史分頁：矩陣按客戶分組

- 每位客戶一行小標題：「客戶名稱 · N 間內地公司」，下面列該客戶的公司，順序照後端現有的「客戶名稱、公司名稱」。
- 公司那一格下方的小字不再重複客戶名稱，只顯示會計公司和「按季」。
- 第 1 點的客戶篩選在這個分頁同樣適用（兩個分頁共用同一個篩選值）。
- 小標題沿用現有樣式類別（參照矩陣現有的行與 `filing-owner`），不自寫顏色、字號；390 寬度下小標題不可被橫向捲動切掉（固定在左側可見範圍內，或在矩陣上方換行顯示）。

### 3. 客戶詳情頁：「報帳報稅」摘要

- 位置：客戶詳情「概覽」分頁，放在「需要處理的事／進行中工單」那兩欄之後，用 `panel` + `panel-head`（`<div><h2>報帳報稅</h2><p>本月進度，詳細操作在報帳報稅頁。</p></div>`），右側一個文字按鈕「查看」，按下打開 `/filings?customer=<ID>`。
- 內容只顯示**本月**，按現有狀態名稱（`filingStatus`：未開始、資料已收、會計處理中、已申報、已完成）計數，例：「本月 11 間：未開始 3、會計處理中 6、已申報 2」，數量為 0 的狀態不列；按季申報而本月不需申報的公司不計入。另列「已逾期 N 期」（含過往月份未完成的），0 時不顯示。「啟用前已處理」「公司已註銷」不計入。
- **只能看，不在客戶頁操作**（避免同一件事兩個入口）。
- 客戶沒有任何報帳期數（沒有內地公司、或報帳報稅由客戶自理）時，**整個區塊不顯示**。
- 本公司自有（`is_self`）同樣適用，有期數就顯示。

### 4. 後端

- `GET /api/filings` 和矩陣接口加可選參數 `customerId`：
  - 有效且屬本租戶 → 只回該客戶的公司。
  - 不存在或別的租戶的 ID → 404「找不到客戶」，不洩露資料。
  - 空字串或沒帶 → 照舊回全部。
  - 客戶帳號 → 照舊 403。
- 客戶詳情頁的摘要用上面的接口取資料，不另開新接口；確有需要另開時在報告寫明理由。
- 不要改 `/api/my/filings` 和 `mobile/`。

### 5. 測試（一個情況一個具名測試）

`customerId`：有效、空字串、不存在、別的租戶、和 `firmId` 同時使用、客戶帳號越權、員工可用。前端：網址帶 `?customer=` 自動選好；帶不存在的 ID 不報錯。
