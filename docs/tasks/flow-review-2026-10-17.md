# 使用流程檢討與建議（負責人 2026-10-17，只是建議，管理者確認前不實做）

管理者意見：目前覺得有點亂；先完整看一次後台和用戶端的使用流程，參考成熟平台的做法給建議；要同時考慮用戶（客戶）和管理者。

檢查方法：本機示範資料，管理端 1366 寬逐頁打開（今日工作、客戶、客戶詳情、牌照、牌照詳情、車輛、業務、出租與租金、收費、報帳報稅、月報、設定），客戶端 390 寬逐頁打開（首頁、牌照、牌照詳情、公司、我的）。

## 一、亂在哪裏

### 管理者（後台）

| # | 發現 | 例子（本機實測） |
|---|---|---|
| A1 | **同一件事在四處都能處理** | 一個到期項目在「今日工作」、牌照總表、牌照詳情、客戶詳情「需要處理的事」都可以填日期、標記完成、開工單，不知道該在哪裏做 |
| A2 | **今日工作塞了太多種東西** | 一個工作隊列混合到期、進行中業務、待錄入、待客戶提供，另有客戶更新待核對、客戶自辦待核對、本月租金、到期概覽、日曆、趨勢圖；30 行隊列每行都有「開工單」（共 48 個） |
| A3 | **牌照詳情太長、處處是輸入框** | 一頁 12 個區塊、高 4120 像素、32 個輸入框、4 個不同的「儲存」按鈕（儲存並核對、儲存、儲存兩地牌、儲存指標資料） |
| A4 | **客戶詳情按鈕太多** | 頂部 4 個按鈕（編輯客戶、套用委託範本、委託範圍、新增）＋ 6 個分頁；客戶帳號一行有 5 個操作 |
| A5 | **對象之間的關係不清楚** | 客戶 → 公司組 → 牌照 → 車輛 → 司機；車輛今天以前只能從客戶頁的分頁進入 |
| A6 | **用語不一** | 「業務」「工單」「開工單」「建立工單」並用；「兩地牌」「牌照」「指標」並用；設定頁仍有「新增自訂規則」 |

### 客戶（用戶端）

| # | 發現 | 例子（本機實測） |
|---|---|---|
| C1 | **改東西有三條路，客戶分不清** | 「修改」（直接改，顧問核對）、「續期／換車／換司機」（自行辦理更新）、「申請辦理」（交我們辦）；牌照頁頂部 4 個按鈕和下方 4 個「修改…」連結並存 |
| C2 | **三個收件匣** | 首頁「需要你處理」、「到期提醒」、鈴鐺「通知」（5 則未讀）各自一處 |
| C3 | **牌照詳情太長** | 手機上高 3464 像素、約 10 個區塊；批文卡模擬卡佔中間大位置，要往下捲很久才到車輛和證件 |
| C4 | **同樣內容重複** | 顧問聯絡和辦理記錄在首頁和「我的」都有 |
| C5 | **空白頁不教下一步** | 「公司」頁只寫「資料由你的顧問整理後會顯示在這裡」 |

## 二、成熟平台怎樣處理

| 平台 | 做法 | 對我們的啟示 |
|---|---|---|
| **Fleetio**（車隊管理）[車輛頁](https://help.fleetio.com/en_US/vehicle-overview)、[續期提醒](https://help.fleetio.com/en_US/vehicle-renewal-reminders) | 一部車一頁，頂部是概覽，資料按分頁放（概覽、提醒、文件…）；所有續期提醒（驗車、保險、登記）集中在「提醒」 | 牌照／車輛頁用「概覽＋分頁」，不要一長頁 |
| **TaxDome 客戶入口** [客戶首頁](https://client-help.taxdome.com/article/1885-client-dashboard) | 首頁就是一個待辦清單：要上傳的文件、要簽的、要付的帳單；做完自動消失。入口只有待辦、文件、帳單、訊息 | 客戶只需要一個「待辦」，不要三個收件匣 |
| **AppFolio／Buildium 業主入口** | 業主只看：月結單、文件、要確認的事 | 客戶端以「看」為主，改動走一條路 |
| **HubSpot** 客戶記錄 | 左邊摘要、中間活動記錄、右邊關聯對象（公司、交易） | 客戶、牌照、車輛頁用同一版型，互相連結清楚 |

共同點：**一個對象一頁、同一版型；一件事只在一個地方做；客戶只有一個待辦清單。**

## 三、建議

### 給管理者（後台）

| 優先 | 建議 | 解決 |
|---|---|---|
| 1 | **對象頁統一版型**：客戶、牌照、車輛三種頁面一樣——頂部摘要卡（重要狀態＋一個主要按鈕），下面分頁；平時只看，改資料按「修改」彈窗。牌照頁分頁：概覽（批文卡＋狀態）／到期與過關／車輛與司機／出租／委託與收費／記錄 | A3、A4、A5 |
| 2 | **今日工作只放「要我做的」**：一個清單按緊急排序；「客戶更新待核對」和「客戶自辦待核對」合成一個「待核對」分頁；租金、趨勢圖移去各自的頁面；每行只留一個主要動作，其他收進「⋯」 | A2 |
| 3 | **一件事只在一處做**：到期項目只在「今日工作」和對象頁的「到期」分頁處理，兩處是同一個組件；牌照總表只看不改 | A1 |
| 4 | **用語統一表**（寫入設計規範）：工單（不叫業務）、牌照（指標只用在「指標類別」）、到期事項（不叫規則） | A6 |
| 5 | 已在規劃的**減少填寫**（`simplify-entry-plan.md`）併入第 1 項一起做 | A3 |

### 給客戶（用戶端）

| 優先 | 建議 | 解決 |
|---|---|---|
| 1 | **一個待辦清單**：首頁頂部「待辦」＝需要你處理＋快到期／已逾期＋未讀通知，做完自動消失；鈴鐺只看歷史 | C2 |
| 2 | **改東西只有一個入口**：牌照頁一個按鈕「有變動？」，問一條：①「我已經自己辦好」（自行辦理更新）②「請顧問幫我辦」（申請辦理）③「資料有錯字」（直接修改）| C1 |
| 3 | **牌照頁精簡**：頂部狀態和「下一件要做的事」；批文卡縮成小圖，點開才看全卡；其他區塊預設收起，標題列顯示摘要（例如「車輛證件 3/6 已上傳」） | C3 |
| 4 | **不重複**：顧問聯絡只放「我的」；辦理記錄只放首頁「辦理中」 | C4 |
| 5 | **空白頁教下一步**：例如公司頁「還沒有公司資料。你的顧問會在 X 天內整理；或按這裏上傳商業登記證」 | C5 |

## 四、建議的進行方式（放慢節奏）

1. 管理者看本文件，決定先做客戶端還是後台、哪幾項。
2. 負責人畫**線框圖**（只畫版面，不寫程式）：牌照頁、今日工作、客戶首頁三張，給管理者確認。
3. 確認後一項一項做，每項先在本機給管理者看，同意才提交部署。
