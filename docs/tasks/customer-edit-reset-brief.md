開始前先讀 `AGENTS.md`，再讀本文件。

## 一、為甚麼要做

李先生的資料已放上正式環境，管理者發現兩件事做不到：

1. 客戶建立後，**名稱、類型、電話都改不了**，系統只支援刪除整個客戶。
2. **客戶登入密碼不能重設**。李先生的兩個帳號仍是本機測試密碼，交給客戶前必須改掉。只要客戶已有帳號，「開通登入」按鈕就會隱藏，所以也不能另開新帳號。

## 二、編輯客戶

### 後端：`PATCH /api/customers/:id`（寫在 `api/src/server.js` 現有 `customerMatch` 旁邊，風格一致）

- 只限管理者（`role === 'admin'`），員工與客戶 403。
- 找不到，或是別的租戶的客戶 → 404「客戶不存在」。
- 請求內容必須是物件：`null`、陣列、字串 → 400「內容無效」。
- 可改欄位：`name`、`kind`、`phone`。只改有送來的欄位；沒送的保持原值。
  - `name`：去頭尾空白後不可為空 → 400「請填寫客戶名稱」；長度上限 120（同新增）；同一租戶內**不可與其他客戶同名** → 409「已有同名客戶」（CSV 匯入按客戶名稱配對，同名會令匯入失敗）。
  - `kind`：只接受「個人」「公司」 → 否則 400「客戶類型無效」。
  - `phone`：可清空（空字串存 `null`）；長度上限 40（同新增）。
  - 欄位類型錯誤（例如 `name` 是數字或物件）→ 400。
- **本公司（自有）**（`is_self`）可改名稱和電話，**不可改類型** → 409「本公司（自有）的類型不可更改」。
- 回傳更新後的客戶（同 `POST` 的回傳格式）。
- 操作記錄：沿用現有 `audit` 機制，確認「設定 → 操作記錄」能看到這次修改。

### 管理端：客戶頁（`admin/src/views/CustomerDetail.vue`）

- 客戶頁頂部深色卡片的按鈕區（「開通登入」「套用委託範本」「委託範圍」旁），加 **編輯客戶**，只有管理者看得到。
- 彈窗沿用新增客戶的 `FormDialog`（`components/RecordModal.vue` 的 `modal === 'customer'` 那組欄位）：客戶名稱（必填）、類型（個人／公司）、聯絡電話。打開時帶入現有值；本公司（自有）的類型欄位停用，旁邊用一行小字說明原因。
- 儲存成功後，頁面和左側清單即時顯示新名稱，並用現有的成功提示；失敗時錯誤顯示在彈窗內，不關閉彈窗。

## 三、重設客戶登入密碼

### 後端（已存在，只補一點）

`POST /api/customer-users/:id/reset-password` 已在 `api/src/security.js`，並有測試（`security.test.js` 第 93–96 行）。**不要改動現有行為與測試**，只補：

- 重設成功後，清除這個帳號的登入失敗鎖定（客戶忘記密碼時多半已被鎖），沿用 `clearFailures('customer', <登入名>)`；客戶可用電郵或手機登入，兩個鍵都要清。
- 請求內容是 `null`、陣列時回 400（現在 `body?.password` 會落到 `passwordProblem`，確認結果是 400 而不是 500）。

### 管理端：客戶頁「概覽 → 客戶帳號」表格

- 每行操作加 **重設密碼**（在「產生微信綁定碼」與「停用」之間），只有管理者看得到；停用的帳號也可以重設。
- 彈窗沿用 `admin/src/views/Staff.vue` 的重設密碼彈窗模式：標題「重設<顯示名稱>的密碼」，一個新密碼欄位，說明「至少 10 個字元，不可與帳號相同」。**送出按鈕的停用條件改成 `< 10`**（Staff.vue 寫的是 8，與規則不一致，Staff.vue 這次一併改正）。
- 成功後：彈窗改為顯示可複製的**轉發文字**（登入網址、帳號、新密碼），做法與「開通登入」成功後的轉發文字相同（`RecordModal.vue` 的 `welcome`／`copyWelcome`）；並提示「原有登入已全部失效」。關閉彈窗後密碼不留在畫面上。
