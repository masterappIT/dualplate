# 客戶生命周期：新增登入、刪除空白客戶、結束服務（2026-10-18）

管理者 2026-10-18 在正式環境提出三個問題：不能刪除客戶、不能加自有客戶、一位客戶只能開一個登入。三件事是同一個缺口：後台只做了客戶的開頭（新增），中間（加登入）和結尾（結束、刪除）不完整。

## 一、管理者決定（2026-10-18）

1. **有資料的客戶不刪除，改為「結束服務」**：保留資料、可恢復。按負責人建議。
2. **托管客戶可開多個登入，全部權限相同**（V1 計劃第 48 行的做法），不分主帳號和助手。按負責人建議。
3. **自管客戶暫時只有一個登入**，但：
   - 多登入的能力要保留，日後開收費方案時只需放開限制，不用重做；
   - 客戶端要讓自管客戶知道「多人登入」是之後推出的收費功能（需求文件 5.6.2 第 6 點：分主帳號和助手，屬收費功能，免費只有一個帳號）。
4. **自有客戶不改**：每個租戶只有一個（IM MASTER INC. LIMITED），公司自己的公司和牌照都放在它名下。只補說明文字。

## 二、三種「不再要這位客戶」的情況

| 情況 | 處理 |
|---|---|
| A. 建錯或測試（沒有業務資料） | 刪除，連同登入帳號 |
| B. 托管客戶結束合作 | 結束服務：資料保留、唯讀、可恢復 |
| C. 客戶按私隱條例要求刪除個人資料 | 自管客戶已有「自行注銷」；托管客戶要等保存期限屆滿，本次不做 |

## 三、分步

每步單獨在本機做完、看過 1366 和 390 兩個寬度、管理者確認後才提交和部署。

### 第 1 步：新增登入，以及自管客戶的說明

後端
- `POST /api/customer-users`：托管客戶不限數量（現在已是如此，補測試鎖定）。
- 自管客戶已有一個登入（啟用或停用都算，刪除的不算）時，回 409「自管客戶目前只可開一個登入，多人登入稍後推出（收費功能）」。限制寫成一條規則（一個常數或函數），日後放開只改一處。
- 已結束服務的客戶不能開登入（第 3 步加上後一併檢查）。

管理端（`admin/src/views/CustomerDetail.vue`）
- 托管客戶：「客戶帳號」區塊標題列常駐「新增登入」按鈕，不再在開了第一個後消失；頂部「開通登入」按鈕只在還沒有登入時顯示，避免兩個入口。
- 自管客戶：已有登入時不顯示新增按鈕，區塊說明寫「自管客戶目前只可開一個登入」。

客戶端（`mobile/src/pages/profile/profile.vue`，負責人親自寫）
- 托管客戶：維持現有「其他可登入的人」和「要新增或停用登入，請聯絡你的顧問」。
- 自管客戶：新增一小段「多人登入」：「讓助手或同事用自己的帳號一起管理。之後推出，屬收費功能。」只是告知，沒有按鈕。

測試（一個情況一個測試）
托管開第二、第三個登入；自管開第二個被拒；自管的唯一登入刪除後可再開；手機或電郵重複；別的租戶的客戶；員工（非管理員）；自有客戶；已注銷客戶；空值、空白字串、`null`、陣列、錯誤類型。

### 第 2 步：刪除空白客戶

後端
- `DELETE /api/customers/:id`：沒有業務資料、只有登入帳號的客戶，可連同登入帳號一併刪除（同一交易內，連帶刪除綁定碼、登入記錄等依附資料）。
- 新增唯讀接口回傳「能否刪除、會刪除哪幾個登入、名下有甚麼資料」，讓確認框顯示。
- 有業務資料時維持 409，訊息改為「名下有牌照等資料，請用『結束服務』」。

管理端
- 刪除入口從「編輯客戶」彈窗底部移到客戶頁頂部操作，只對空白客戶顯示。
- 確認框列明會刪除的登入帳號（姓名、手機或電郵）。
- 有資料的客戶不顯示刪除，改顯示「結束服務」（第 3 步）。

測試：空白客戶；只有登入的客戶；有各類業務資料的客戶；自有客戶；別的租戶；員工；不存在的 ID；重複刪除。

實際做法（2026-10-18 完成）
- `GET /api/customers/:id/deletion` 回傳能否刪除、名下有甚麼（擋住刪除的資料）、會一併刪除的登入。
- 刪除時要送上確認的登入數目（`{ logins: N }`），與當時的數目不同就要重新確認，避免確認框打開後別人又開了登入。
- 「業務資料」在原有清單上加了自行辦理記錄和訊息往來；同意條款記錄、綁定碼、委託項目、自訂價錢、模式記錄、申請記錄、客戶端改動記錄和通知隨客戶一併刪除。
- 「編輯客戶」彈窗不再放刪除按鈕；不能刪除時在彈窗底部說明名下有甚麼。第 3 步加上「結束服務」後再改為指向它。

### 第 3 步：結束服務、恢復服務

後端
- 客戶新增「結束服務日期、原因、操作人」欄位（與自管注銷的 `closed_on` 分開，兩者意思不同）。
- 結束時：所有登入停用；不再產生到期提醒、年費、報帳；不出現在今日工作；資料唯讀（寫入接口回 409）。
- 結束前回傳未完成的工單和未收的費用，提醒但不阻止。
- 恢復服務：清除結束標記，重新啟用結束時被停用的登入（原本已停用的保持停用）。
- 只限托管客戶；自管客戶用自行注銷，自有客戶不可結束。

管理端
- 客戶頁「結束服務」按鈕和確認框（日期、原因、未完成事項清單）。
- 已結束的客戶頁頂顯示狀態和「恢復服務」，其他編輯操作隱藏。
- 客戶列表默認不顯示已結束客戶，篩選加「已結束」。

客戶端
- 已結束客戶登入時看到「服務已於某日結束，如需恢復請聯絡我們」，不能進入。

測試：結束和恢復各自的權限、租戶、重複操作；結束後提醒、收費、報帳、今日工作都不再出現；結束後寫入被拒；恢復後只重新啟用原本啟用的登入；自管客戶和自有客戶被拒。

實際做法（2026-10-18 完成，負責人自行判斷的地方標＊）
- 後端集中在 `api/src/customer-lifecycle.js`：`GET/POST /api/customers/:id/end-service`、`POST /api/customers/:id/restore-service`。
- 只可查看：按網址找出修改請求屬於哪位客戶（客戶、牌照、車輛、證件、驗車、公司、公司組、司機、登入、出租），新增請求按內容的 `customerId`（開登入、牌照、車輛、公司、公司組、司機、工單）。員工和管理者一樣受限。
- ＊結束後仍可處理收費、收款、報價、租金結算和已開工單的進度，方便結清；不能開新工單。
- ＊結束日期不可遲於今天，不支援預先設定將來的結束日。
- ＊結束當月仍產生月報（交代最後一個月），之後不再產生。
- 未報的報帳期數標為「客戶已結束服務」，恢復時重開。
- 「結束服務」按鈕只對有業務資料的托管客戶顯示；沒有業務資料的用「刪除客戶」。
- 客戶端不用改：已結束的客戶用正確密碼登入時，登入頁顯示「你的服務已於某日結束，帳號已停用。如需恢復服務，請聯絡我們。」；密碼錯誤時照常顯示「帳號或密碼不正確」。
- 未涵蓋：牌照 CSV 匯入（按客戶名稱）、`/api/service-scopes`、`/api/tracked-items`、`/api/rule-completions` 這類按內容指定對象的請求未被擋（管理端已收起入口）；微信登入沒有專門說明（正式環境未開微信登入）。

### 第 4 步：自有客戶說明（2026-10-18 完成）

客戶頁和客戶列表中自有客戶的說明加一句「公司自己的公司和牌照都放在這裏」。

## 四、驗收

- 每步：`cd api && npm test`、`cd admin && npm run check && npm run build`、客戶端建置。
- 每個改動畫面看 1366 和 390，彈窗實際點開，按 `docs/visual-qa-checklist.md` A–H 逐頁自查。
- 三步完成後在本機跑一次閉環：建托管客戶 → 開兩個登入 → 兩個都能登入 → 結束服務 → 兩個都不能登入、提醒消失 → 恢復 → 能登入；建空白客戶 → 開登入 → 連同登入刪除。
