# 任務：委託範圍矩陣按香港公司／澳門公司／內地公司／牌照分段（負責人 2026-10-17）

開始前先讀 `AGENTS.md`，再讀本文件。**等報帳報稅頁第二輪、`company-names-brief.md` 都驗收後才開始**（兩者都改 `CustomerDetail.vue`），本任務不需要雲端操作，也不要發布。

## 一、管理者的意見（2026-10-17）

1. 委託範圍矩陣「沒有做香港公司／內地公司／車牌分類」。
2. **每月報帳只適用內地公司。**

現在的問題：
- 客戶詳情「委託範圍」抽屜（`CustomerDetail.vue` 的 `matrixOpen`、`admin/src/components/business/ServiceScopeMatrix.vue`）把所有公司和牌照排成一個列表，欄固定是 6 個服務項目。每行只顯示名稱，**分不出香港公司還是內地公司**。
- 每一類對象只有 2–3 欄適用，**約一半格子是「不適用」**。
- 不能整類一次設定，例如李先生「香港公司全部客戶自理」要逐格點。

## 二、後端：每月報帳只適用內地公司

1. `api/src/entrustment.js` 的 `serviceApplies`：`bookkeeping` 只在 `owner.jurisdiction === '內地'` 時適用。香港、澳門公司送 `bookkeeping` → 400「此服務項目不適用於這個對象」（沿用現有訊息）。
2. **澳門稅項規則改歸「審計及報稅」**：`api/src/rules.js` 的 `mo_tax`（澳門營業稅／所得補充稅申報）`service` 由 `bookkeeping` 改為 `audit_tax`。`db.js` 預設規則同步那一段只更新 `service IS NULL` 的規則，所以要**另加一次性遷移**（沿用 `schema_migrations`），把各租戶 `code='mo_tax' AND service='bookkeeping'` 的規則改為 `audit_tax`。管理者自訂的其他規則不要動。
3. **現有委託記錄的遷移**（同一個遷移內，按「修改時保留歷史」的做法）：
   - 香港、澳門公司現行的 `bookkeeping` 記錄：填上 `ended_on`（遷移當日），`notes` 寫「每月報帳只適用內地公司，系統結束此項」。不刪除。
   - 澳門公司：結束 `bookkeeping` 前，如果該公司**沒有**現行的 `audit_tax` 記錄，就以相同的 `handler`、`provider_name` 新建一條 `audit_tax` 記錄，令 `mo_tax` 的負責方不因改歸而變動。已有 `audit_tax` 記錄的，不覆蓋。
   - 遷移只跑一次；重跑不得重複結束或新建。
4. `templateChanges`（委託範本）只用 `servicesFor` 產生項目的話會自動跟隨；請核實三個範本套用到香港、澳門公司時都不會產生 `bookkeeping`。
5. 介面上 `audit_tax` 的名稱：香港公司顯示「審計及利得稅」，澳門公司顯示「審計及報稅」（澳門沒有「利得稅」這個稅種）。`serviceLabels` 保持一個代碼一個預設名稱；按司法區換名稱的做法由你決定，但 API 回傳的 `label` 和管理端顯示必須一致。
6. 報帳報稅模組（`api/src/bookkeeping.js`）本來就只處理內地公司，不用改。

## 三、管理端：矩陣分段

沿用現有 `Drawer`、`ServiceScopeMatrix` 和 `scope-matrix-*` 樣式類別，不要另寫一套表格。抽屜由上到下分段，**沒有對象的段落不顯示**：

| 段落 | 欄（只列適用的） | 每行顯示 |
|---|---|---|
| 香港公司 | 公司維護、審計及利得稅、公司秘書 | 中文名稱；下一行次要文字顯示英文名稱（按 `company-names-brief.md` 第二節第 5 點，沒有時顯示警示色「未填英文名稱」）及所屬牌照 |
| 澳門公司 | 公司維護、審計及報稅 | 名稱；次要文字顯示所屬牌照 |
| 內地公司 | 公司維護、每月報帳 | 簡體名稱；次要文字顯示所屬牌照 |
| 牌照 | 牌照代辦、出租代管 | 牌照號碼（沿用 `PlateChip`） |

1. **欄由後端決定**：每段的欄取自 `GET /api/service-scopes` 回傳的 `services`，不要在前端另寫一份「哪類公司有哪些欄」的清單。`CustomerDetail.vue` 第 171 行固定的 `matrixServices` 改為按段計算或移除。
2. **所屬牌照**：公司經公司組連到牌照。一間公司持有多個牌照時全部列出，以「、」分隔；沒有牌照的寫「未掛牌照」。用現有已載入的 `companyGroups`、`customerPlates` 計算，不要為每行多打一次 API。
3. **段落標題**：用現有的段落標題樣式（參照 `panel-head` 的 `<div><h2/><p/></div>`），`h2` 寫段名和數量，例「香港公司（3）」。
4. **整欄設定**：每段的欄標題可以按，按後彈出選單「全部改為：我們做／外包／客戶自理」（自有客戶不顯示「客戶自理」，沿用 `isSelf` 的限制）。選了只把**這一段**這一欄的格子加入待提交改動，和逐格點擊一樣累計，確認後才提交。選單用現有的下拉或選單組件，不用瀏覽器 `prompt()`。
5. **外包單位**：整欄改為「外包」時，在抽屜下方只出現**一個**「〔段名〕·〔欄名〕外包單位」欄位，填一次套用到該欄全部格子；之後逐格再改的照常各自顯示一個欄位。現有逐格外包欄位的標籤要加上段名，例「內地公司 · 广州远星商贸有限公司 · 每月報帳外包單位」。
6. 逐格點擊循環切換、懸停高亮、`aria-label` 照現有做法保留。
7. 桌面寬度抽屜維持 900px。390px 時每段只有 2–3 欄，**不得出現橫向捲動**；名稱和次要文字可以換行，但不可截掉。
8. 公司卡片上的「委託範圍」區塊（`admin/src/components/ui/ServiceScope.vue`）的項目也來自 API，改完後香港、澳門公司不應再出現「每月報帳」；請核實並截圖。

## 四、測試（一個情況一個具名測試）

後端（放在 `api/test/entrustment.test.js` 或新檔）：
- 香港公司 `PUT /api/service-scopes` 送 `bookkeeping` → 400。
- 澳門公司送 `bookkeeping` → 400。
- 內地公司送 `bookkeeping` → 200。
- 香港、澳門公司的 `GET /api/service-scopes` 不含 `bookkeeping`；內地公司含有。
- 澳門公司 `audit_tax` 的 `label` 為「審計及報稅」，香港公司為「審計及利得稅」。
- 遷移：香港公司現行 `bookkeeping` 記錄被結束，歷史保留。
- 遷移：澳門公司沒有 `audit_tax` 時，以原 `handler`、`provider_name` 新建。
- 遷移：澳門公司已有 `audit_tax` 時不覆蓋。
- 遷移：重跑不重複結束、不重複新建。
- 遷移：`mo_tax` 規則的 `service` 變為 `audit_tax`；其他規則不變。
- `mo_tax` 到期項目的 `handler` 跟隨澳門公司的 `audit_tax`。
- 三個委託範本套用到香港、澳門公司時都不產生 `bookkeeping`。
- `PUT /api/service-scopes/batch` 混入一項香港公司 `bookkeeping` → 整批 400，其他項目沒有寫入。
- 空值、`null`、陣列、錯誤類型、不存在的 ID、別的租戶的公司 ID、客戶帳號越權，照 `AGENTS.md` 第 3 點。

**現有測試**：如果有測試斷言香港或澳門公司可以設定 `bookkeeping`，那是本次管理者改了業務規則，可以只改那一條斷言，並在報告列出檔名、行號和改動前後的內容。其他測試不得刪除或放寬。

前端：改完 `.vue` 後跑 `cd admin && npm run check`。
