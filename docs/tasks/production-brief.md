# 任務：上線準備（第 21 輪）

先讀 `AGENTS.md`。本任務在月報（第 20 輪）驗收後進行。目標：V1 可以安全地給管理者團隊與客戶試用。

## 1. 資料安全

- **每日自動備份**：`api/scripts/backup.js` 用 SQLite 線上備份 API 輸出到 `BACKUP_DIR`（環境變數），保留 30 天；`npm run backup` 可手動執行；附還原說明與還原演練測試（從備份啟動、資料一致）
- **操作記錄**：新表 `audit_logs`（誰、何時、甚麼對象、改了甚麼欄位前後值、IP）；寫入點：客戶、公司、牌照、到期日、委託範圍、轉讓、工單結案、收費、收款、月報確認、帳號與權限；設定頁「操作記錄」用腳手架操作日誌的泳道與列表（`docs/design-system.md` 第九節）
- 敏感欄位（身份證、回鄉證號）在列表與記錄中遮蔽
- 上傳檔案：檢查真實檔案類型（檔頭）而非副檔名；大小上限

## 2. 帳號安全

- 密碼至少 10 位、不得與帳號相同；登入失敗 5 次鎖 15 分鐘（按帳號與 IP）
- 會話 30 天、閒置 7 天失效；改密碼後其他會話失效
- 管理端「修改密碼」；管理者可重設員工與客戶密碼

## 3. 運行

- 環境變數集中說明 `api/.env.example`（不含真實值）：`PORT`、`DB_PATH`、`CORS_ORIGINS`、`BACKUP_DIR`、`WECHAT_APPID`、`WECHAT_SECRET`
- `GET /api/health`：資料庫可讀、版本號
- 錯誤記錄：伺服器錯誤寫入 `logs/`（按日），不把錯誤細節回傳給前端
- 部署說明 `docs/deploy.md`：一台雲伺服器（Node 22、Nginx 反向代理、HTTPS 憑證、pm2 或 systemd）、管理端與客戶端 H5 靜態檔、小程序上傳步驟；香港與內地伺服器的差異（內地需 ICP 備案）
- 示範資料：`DEMO_SEED=1` 產生完整閉環示範（2 位客戶含本公司自有、12 個牌照、公司組、到期、工單、合約、收費、月報），供管理者測試

## 4. 安全檢查

- 逐條檢查所有 API：未登入 401、客戶越權 403/404、員工越權 403、別的租戶 404；以自動化測試覆蓋（可用路由表產生）
- 檢查 SQL 全部參數化、無字串拼接；回應不洩露內部欄位

## 5. 測試

具名、一情況一測試覆蓋第 1–4 節。`npm test`、`npm run check`、兩端 build 全過，測試數量不減。

## 限制

遵守 `AGENTS.md`。不連接真實外部服務；不讀寫 `api/data/`。
