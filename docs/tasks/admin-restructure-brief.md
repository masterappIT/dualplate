# 任務：管理端結構重整（今日工作、客戶一頁看全、牌照總表）

先讀 `AGENTS.md`。本任務在「管理端拆分」驗收後進行，直接在拆分後的組件上修改。背景見 `docs/ui-audit.md`；管理者已確認的畫面示意如下（文字描述）。

## 1. 導航與品牌

- 側欄改為：**今日工作**、**客戶**、**牌照**、**業務**、**設定**（租金、報稅兩項等對應模組完成後才出現）
- 移除獨立的「管理總覽」「案件工作台」「公司與指標」「車輛與牌證」「官方來源」導航：內容分別併入下列頁面；舊網址或程式內的 `view` 值要導向新頁面，不能出現空白頁
- 「設定」內含：規則設定、官方來源（日後會加會計公司、員工、合約範本）
- 品牌改為「車牌管家」，去掉「OPERATIONS HUB」；登入頁說明改為「管理客戶的兩地牌、公司與到期事項。」；側欄每項用不同圖示

## 2. 今日工作（取代管理總覽和案件工作台）

- 上方 4 個數字：已逾期、7 天內要辦、待錄入資料、進行中業務（租金和報稅模組完成後再加對應數字）
- 分頁：**到期待辦**（逾期＋需處理）、**進行中業務**（未完成的案件）、**待錄入**、**待客戶提供**（狀態為「待客戶配合」的案件節點）
- 每列直接操作，不用跳頁：
  - 手動到期項目：**列表上直接填日期並儲存**（用現有 `PUT /api/tracked-items`）
  - 來自批文卡的日期：顯示「到批文卡修改」連結
  - 推算型項目：「已辦好」＝標記本期完成
  - 「開工單」：建立案件並帶入對象與業務類型（批文、CRP、澳門通行證 → 續期；驗車 → 驗車代辦；其他 → 其他代辦要求）；建立後進入案件詳情
- 可按客戶篩選；保留現有按狀態篩選

## 3. 客戶（一個客戶一頁看全）

- 客戶列表改為表格：名稱、類型、牌照數、公司組數、狀態燈（沿用總覽的健康判斷）、下一個到期；可搜尋
- 客戶詳情分頁：
  - **概覽**：需要處理的事（該客戶的逾期／需處理／待錄入數）、進行中業務、牌照與公司數
  - **公司組**：搬入現有「公司與指標」的全部功能（新增公司組、公司、狀態、香港公司註冊處查詢、公司到期項目），客戶已固定，不用再選客戶；表格欄位：香港／澳門公司、內地公司、牌照、狀態標籤
  - **牌照**：該客戶的牌照總表（同第 4 節欄位）
  - **車輛與司機**：車輛列表；司機名單取自各牌照批文卡上的駕駛人
  - **業務**：該客戶的案件
- 頁首顯示客戶名稱、類型、牌照數、公司組數，以及「開通登入」「新增」（牌照、車輛、公司組、案件）

## 4. 牌照總表（新頁）

- 全部牌照一張表：車牌（內地·港澳）、持牌公司（公司組的香港／澳門公司，沒有則用批文卡商號）、客戶、口岸、批文到期（`card_expires_on`）、CRP／澳門通行證到期、使用（自用／出租／空置）、狀態（該牌最嚴重的到期狀態，沒有任何日期為「資料不全」）
- 篩選：全部、需注意、出租中、自用、空置、資料不全；可搜尋
- **表格內直接填 CRP／澳門通行證日期**
- **批量填日期**：勾選多個牌照 → 選規則 → 填日期 → 一次儲存
- **CSV 匯入**（Excel 另存 UTF-8 CSV；不新增依賴）：欄位為客戶、路線、內地車牌、港澳車牌、批文卡號、批文到期、CRP／通行證到期、香港／澳門公司、內地公司。先上傳預覽：逐列顯示將新增或更新的內容和錯誤，確認後才寫入；同一客戶＋路線＋批文卡號視為同一牌照（更新不重複）。新增 API `POST /api/import/plates?dryRun=1`
- 點車牌進入現有兩地牌詳情

## 5. 移除舊「牌證」系統

- 一次性遷移：把舊 `credentials` 中可對應的記錄轉入到期項目（名稱含「封閉道路通行許可證」→ `hk_crp`；含「澳門」且含「通行證」→ `mo_permit`；含「批文」→ 略過，以批文卡為準）；其餘轉成該車輛的備註並在報告列出
- 管理端移除「牌證日期提醒」「新增牌證」「牌證」面板；相關 API 改為唯讀（保留給舊資料查詢），不再寫入
- 客戶端的舊牌證讀取若仍有引用，在報告列出，由負責人處理（你不要改 `mobile/`）

## 6. 不變的部分

- 批文卡前端效果（模擬卡、正反翻轉、上傳辨識、修改內容、原件核對）不變；兩個 `ApprovalCard.vue` 不改
- 案件詳情暫時沿用現有樣式（下一個任務「工單改版」才重做）
- 不改 `mobile/`
