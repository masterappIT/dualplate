# 任務：報帳報稅頁面整理（負責人 2026-10-17）

開始前先讀 `AGENTS.md`（特別是「分工」「看畫面的方法」），再讀本文件和 `docs/tasks/bookkeeping-brief.md`（原業務規則，**全部照舊**）。本任務在 Codex 桌面 app 做。

## 一、管理者的反映與負責人的診斷

管理者說「報帳報稅的操作太亂」。負責人實際看過頁面（`admin/src/views/Filings.vue`），問題是：

1. **同一件事顯示兩次**：上方「進度矩陣」和下方「需要跟進」列的是同一批期數，整頁約 2,600 像素高。
2. **系統啟用前的舊期數全是紅色逾期**：今天才導入資料，8、9 月自動補生後全部「已逾期」（22 期），真正要做的事被淹沒。管理者已確認：這些在系統外**已處理完**。
3. **一次性設定混在每月操作裏**：會計公司、申報週期只能在每一期的彈窗裏改，所有公司都顯示「未指定會計公司」。
4. **每期彈窗有 10 個控件**（4 個日期＋4 個「今天」、申報類型、稅額、會計公司、週期、回執、備註），看不出現在該做哪一步。
5. **沒有批量操作**：每月把 11 間公司的票據交給同一家會計公司，要開 11 次彈窗。

參照 `docs/v1-plan.md` 第五節指定的 TaxDome／Karbon：工作按階段推進、一鍵到下一步、可批量。

## 二、要做的事

### 1. 頁面結構（`Filings.vue`）

- 標題區照舊（`PageHeader`，右側「截止日」「會計公司」）。統計卡照舊，點卡片篩選下面的清單。
- 統計卡下面用 `Segmented` 切換兩個分頁：**本月工作**（預設）｜**歷史**。不要再上下疊兩個列表。
- 「歷史」分頁 = 現在的進度矩陣（不改邏輯，點格子照樣打開該期）。

### 2. 本月工作分頁

- 一間公司一行，顯示「需要處理」的期數：未完成的期數按截止日排序（逾期、需處理在前）；已完成、已註銷、啟用前已處理的不顯示。某公司若有多期未完成，每期一行。
- 欄位：勾選框、公司（下方小字：客戶・會計公司）、期數、目前步驟（`StatusTag`）、截止（`DueDate`）、操作。
- 操作欄只有**一個主要按鈕「下一步：<步驟名>」**（例：「下一步：已交會計公司」），按下即把該步驟記為今天並儲存，不開彈窗；**唯獨到「已申報」這一步**要先填申報類型（正常／零申報）和稅額，按鈕改為打開小彈窗填這兩項。旁邊一個文字按鈕「詳情」打開完整彈窗。
- 勾選多行後，清單上方出現批量列（參照現有頁面的批量做法，不自創樣式）：「標記為：客戶票據收齊／已交會計公司」（已申報、已繳款不提供批量，因為要逐間填稅額），以及「標記為系統啟用前已處理」。批量只對「下一步正好是所選步驟」的期數生效，其餘略過，並在結果提示寫明「已更新 N 期，略過 M 期（原因）」。
- 頂部提示（`panel` 內一行，非彈窗）：有公司未指定會計公司時顯示「N 間內地公司未指定會計公司」＋按鈕「設定」，打開第 3 點的公司設定。
- 空狀態：「本月沒有待處理的報帳」。

### 3. 公司設定（一次性，從頁面提示或「會計公司」旁的新按鈕「公司設定」進入）

- 彈窗或抽屜（沿用 `FormDialog` 或 `Drawer`）：表格列出所有需報帳的內地公司，欄位：勾選、公司、客戶、會計公司、申報週期。
- 勾選多間後可一次指定同一家會計公司和申報週期；也可逐行改。
- 後端加 `PUT /api/companies/filing-setup`（批量）：body `{ companyIds: [...], accountingFirmId, filingCycle }`；沿用現有單間 `PUT /api/companies/:id/filing-setup` 的驗證。
- 每期彈窗裏**移除**會計公司和申報週期兩個欄位。

### 4. 每期詳情彈窗（精簡）

- 頂部步驟條（1 票據收齊 → 2 已交會計公司 → 3 已申報 → 4 已繳款／零申報則到 3 為止），已完成的步驟顯示日期，目前步驟高亮。
- 主體只顯示**目前步驟**需要的輸入：步驟 1、2 只有日期（預設今天）；步驟 3 加申報類型與稅額；步驟 4 只有繳款日期。完成後顯示回執上傳（已申報即可上傳）。
- 「修改已記錄的日期」收在可展開的區塊（例：文字按鈕「修改日期」），展開後才出現 4 個日期欄位。
- 備註保留，放最下面。

### 5. 系統啟用前已處理（後端）

- `filing_periods.closed_reason` 新值 `pre_system`（現有值表示公司已註銷，照舊）。
- `filingStatus`：`pre_system` → `啟用前已處理`；`filingLevel` 視同完成（不逾期、不需處理、**不算缺回執**）；不出現在今日工作和到期列表。
- 新增 `POST /api/filings/bulk`：body `{ ids: [...], action: 'docs_received' | 'sent_to_firm' | 'pre_system' }`。`docs_received`／`sent_to_firm` 記今天日期，只對下一步正好是該步驟的期數生效；`pre_system` 只對尚未申報的期數生效。回傳 `{ updated: [...ids], skipped: [{ id, reason }] }`。
- 客戶端 API `/api/my/filings`：`pre_system` 的期數顯示為「已完成」（客戶不需要知道內部原因）。**不要改 `mobile/`**。
- 已標記 `pre_system` 的期數，在詳情彈窗可「取消標記」（恢復為原狀態），以防標錯。

## 三、測試（`api/test/` 新檔，一個情況一個具名測試）

批量：空陣列、`null`、非陣列、含不存在 ID、含別的租戶 ID（略過且不洩露）、員工與客戶越權、不支援的 action、重複執行（第二次全略過）、步驟不對的期數被略過並寫原因。`pre_system`：不逾期、不缺回執、不在到期列表、客戶端顯示已完成、已申報的期數不能標、可取消標記。批量公司設定：空、`null`、不存在 ID、別的租戶、非內地公司、無效週期、無效會計公司。
