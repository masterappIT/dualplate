# 任務：工單改版與員工帳號（第 14 輪）

先讀 `AGENTS.md` 和 `docs/v1-plan.md`。本任務在第 13 輪驗收後進行。

**參照 Karbon／TaxDome 的工作流程**：每種業務一條流水線，工單按階段推進（看板）；每張工單有負責人、截止日、步驟清單；需要客戶提供的資料用「客戶待辦」列出。介面用語：「工單」（不再叫「案件」）。

## 1. 員工帳號與兩級權限

- `users.role`：現有 `admin` 改稱**管理者**；新增 `staff` **員工**；`customer` 不變
- 管理者：全部功能
- 員工：可看全部客戶、牌照、公司；可辦工單、填日期、錄入過關、上傳文件；**不可**：改規則設定、改委託範圍、轉讓牌照、開通／停用帳號、看或改收費（收費模組日後才做，先預留權限檢查函數 `canManage(user)`）
- API 對員工越權一律 403，前端不顯示對應按鈕
- 設定頁加「員工」分頁：列表（姓名、帳號、角色、狀態、最近登入）；新增員工（姓名、帳號、初始密碼）、停用／啟用、重設密碼、改角色；不可停用自己、不可把最後一位管理者改成員工
- 停用的帳號不能登入，現有登入會話即時失效

## 2. 業務範本（流水線）

- 新表 `work_templates`（每租戶一套，遷移時用 `api/src/catalog.js` 的 `routePlans` 和 `services` 產生預設）：`id`、`tenant_id`、`service_code`、`route`、`name`、`steps_json`、`active`、`sort`
- 每個步驟：`title`、`owner`（`us` 我們／`client` 客戶）、`documents`（所需文件名稱清單，可空）、`days`（預計天數，可空）
- 設定頁加「業務範本」分頁：按業務列出，可改步驟名稱、次序、負責方、所需文件、天數；可停用某範本；可新增自訂業務（例如「公司年審」）
- `catalog.js` 的官方來源保留，範本步驟可引用來源 ID

## 3. 工單

- 沿用 `requests` 表並加欄位：`assignee_id`（已有）、`due_on`、`template_id`、`priority`（`normal`／`urgent`）、`completed_at`、`cancelled_reason`
- 狀態簡化為：**待開始、進行中、待客戶提供、已完成、已取消**；遷移舊狀態（新要求→待開始，其餘未完成→進行中，已完成→已完成）
- 步驟沿用 `tasks` 表，加 `owner`、`documents_json`、`completed_by`、`completed_at`、`sort`；建工單時按範本複製步驟
- 規則：
  - 任一 `owner=client` 的步驟未完成且它是下一個未完成步驟時，工單狀態自動顯示「待客戶提供」
  - 所有步驟完成或標「不適用」才可結案；舊有的「廣東批文完成前不能開始港／澳步驟」保留
  - 結案時彈出**「更新到期日」**對話框：按業務類型列出相關到期事項讓員工填新日期（續期→批文、CRP／澳門通行證；備案→海關及邊檢備案；驗車→驗車；換車→提示到牌照詳情更新批文卡），可略過
  - 取消要填原因
- 截止日預設＝建立日＋範本步驟天數總和；可改

## 4. 畫面（「業務」頁）

- 頂部切換：**看板**（按狀態分欄，卡片顯示客戶、車牌、業務、負責人頭像、截止日，逾期紅色）／**列表**
- 篩選：我的工單、全部、按負責人、按業務、按客戶、逾期
- 看板可拖動卡片改狀態（「已完成」須經結案檢查；不能拖到已完成時顯示原因）；窄螢幕不提供拖動，改用卡片上的狀態選單
- 新增工單：選客戶 → 選牌照（可選）→ 選業務（自動帶範本和截止日）→ 選負責人（預設自己）→ 建立；從今日工作「開工單」照樣帶入
- 工單詳情：頂部摘要（客戶、牌照、業務、負責人、截止、狀態）；步驟清單逐項打勾，`owner=client` 的步驟標「客戶提供」，顯示所需文件；右側（窄螢幕在下方）活動記錄；內部備註
- 今日工作的「進行中業務」分頁改用新狀態；上方數字「進行中業務」＝待開始＋進行中＋待客戶提供

## 5. 客戶端相容

- 客戶端頁面本輪**不改**；`customer-routes.js` 本輪**允許修改**，僅為：把新狀態對應成客戶看得懂的文字（待開始→已收到、進行中→辦理中、待客戶提供→需要你提供資料、已完成→已完成、已取消→已取消），並在工單詳情回傳 `owner=client` 的未完成步驟及所需文件（欄位名 `clientTodos`）。現有回傳欄位不可刪，報告逐行說明改動

## 6. 測試（一個情況一個具名測試）

- 員工：每項禁止動作 403；停用後不能登入、現有會話失效；不可停用自己；最後一位管理者不可降級；重設密碼
- 範本：預設產生一次、修改後新工單用新步驟、舊工單不受影響、停用範本不可再選
- 工單：建立帶範本和截止日、自動「待客戶提供」、未完成步驟不可結案、批文前置規則仍生效、取消必須有原因、結案更新到期日寫入 `tracked_items`、略過不寫入、舊資料遷移狀態正確
- 權限與隔離：別的租戶的工單、員工、範本一律 404；客戶不能存取管理 API
- 輸入：空值、null、錯誤類型、不存在的負責人、指派給已停用員工 400
- `cd api && npm test`、`cd admin && npm run check`、`cd admin && npm run build`、`cd mobile && npm run build:h5` 全部通過

## 7. 驗收方式

負責人在 1366px 與 390px 實測：員工管理、用員工帳號登入確認看不到受限功能、業務範本修改、看板拖動與結案檢查、新增工單、工單詳情步驟打勾、待客戶提供自動切換、結案更新到期日、今日工作開工單。

## 限制

遵守 `AGENTS.md`。除第 5 節外不改 `api/src/customer-routes.js`；不改 `mobile/`、兩個 `ApprovalCard.vue`。
