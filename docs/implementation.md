# 可執行首版與部署說明

日期：2026-10-15。此倉庫位於 `/Users/vincentw/development/cross-border-plate-crm`。

## 兩地牌與批文卡（2026-10-15）

- 新增獨立兩地牌台帳。一個客戶可有多個粵港／粵澳牌；上牌狀態（待核對、未上牌、已上牌）、使用狀態（待核對、自用、出租中、暫停使用）分開記錄。未上牌可不綁定車輛；自用已上牌須綁定車輛。出租另有承租方、使用車牌、起訖日及結束記錄。出租狀態只代表內部業務台帳，不推斷官方配額或駕駛資格。
- 每個牌可上傳自己的批文卡正反面 PNG/JPG。上傳後 API 以本機 OCR 辨識欄位，保存為可修改的卡面資料並標為「待核對」；用戶端即時顯示由 SVG 圖形底紋、CSS 文字層與資料欄位組成的模擬正反面，並提供手動修改。管理端看到同一份模擬卡、欄位表和原件掃描核對入口，管理員按「儲存並核對」後標為「已核對」。原件掃描只作核對來源，不直接取代模擬卡預覽；圖片讀取需登入並按客戶隔離。OCR 使用本機 `api/tessdata/chi_sim.traineddata`，不依賴首次上傳時的網絡下載。
- 批文卡檔案以客戶名下的每個兩地牌為單位。每次上傳正面、背面或修改卡面資料都產生新版本，保存當時的欄位、核對狀態、修改人、時間及可用的正反面原件；既有卡在資料庫升級時成為第 1 版。客戶端與管理端均可選擇歷史版本預覽模擬卡，卡面可點擊翻轉正反面。管理端也可查看所選版本的原件掃描。上牌、出租和車輛綁定狀態仍屬於兩地牌台帳，不隨批文卡版本改寫。
- 客戶端「我的兩地牌」以 Apple Pay 式疊層批文卡列出每個獨立牌檔案；卡片使用詳情頁相同的模擬卡元件。點擊任一卡片會在畫面中央獨立預覽，可點卡面翻看正反面；卡下方顯示內地與港澳車牌、上牌及使用狀態，並提供「查看此兩地牌檔案」按鈕。單牌詳情可修改兩地牌台帳、上傳或手改批文卡；「登記批文卡」可建立粵港或粵澳檔案，必須填寫批文卡編號；只有車牌號、尚未取得批文卡時走「申請代辦」。客戶只能建立和修改自己名下的牌，出租使用狀態仍由專員核對。
- 使用者提供的桌面檔案 `兩地牌維護/曲坤批文卡2026-2027.pdf` 已核對為兩頁正反面原件掃描。其裁切圖已匯入本機 `曲坤有限公司` 客戶檔案的粵港兩地牌；此客戶未開通登入。卡號、內地與香港車牌、有效期取自掃描；上牌和使用狀態維持待核對。原始 PDF 仍在桌面，未複製至原始碼倉庫。
- 內地港澳入出境號牌依 [GA 36—2018《中華人民共和國機動車號牌》](https://upload.wikimedia.org/wikipedia/commons/0/00/GA_36-2018.pdf) 第 5 章及附錄 B.8（標準本身由公安部主管，[國家標準信息平台目錄](https://std.samr.gov.cn/hb/search/stdHBDetailed?id=8B1827F150C5BB19E05397BE0A0AB44A)）重繪：440 × 140 毫米比例、黑底白字、白邊與上下固封孔，末字按粵港／粵澳顯示「港」／「澳」。
- 香港本地號牌依 [香港運輸署的《道路交通（車輛登記及領牌）規例》附表 4](https://www.td.gov.hk/filemanager/common/cap%20374e%20schedule%204%20eng.pdf) 重繪：車頭白底黑字、車尾黃底黑字，字形參照該文件圖 3；現有樣式不代表獲批製造商的反光字牌。
- 澳門本地汽車號牌依 [澳門交通事務局《車輛註冊號牌技術規格表》](https://www.dsat.gov.mo/dsat/images/spec_tc_2023.pdf) 重繪黑底白字、`MQ-12-34` 排列與 460 × 100 毫米短系列比例。該規格表還有 520 × 120 毫米闊系列及雙行版；目前畫面使用短系列範本。
- 官方公開的規格與示例能還原號牌類別、主要顏色、比例與排列，但不能證明某個客戶的號牌實物照片、反光材料、專用字模和固封細節逐像素一致。這些資料未包含在使用者提供的批文卡 PDF 中；客戶實物照片須由專員核實後上傳，系統才顯示原圖。

## 申請代辦與現有兩地牌分流（2026-10-15）

- 「申請代辦」保存新申請、續期、換車等案件和辦理節點。提交新申請不建立空白批文卡，也不在「我的兩地牌」卡片疊層出現。
- 「我的兩地牌」只列已有批文卡編號的檔案；每張卡獨立管理卡面版本、車牌、上牌及出租狀態。新增檔案可上傳批文卡正反面作辨識、核對欄位與模擬卡，或手動填寫；同一客戶、路線和批文卡編號不能重複建檔。
- 續期等既有牌代辦可選擇對應兩地牌。管理端在新申請取得正式批文卡後，可從該案件建立新檔案，系統自動關聯案件與卡片；客戶可從案件進度打開相關檔案。尚無批文卡號的舊記錄保留在管理端供人工整理，不在客戶的卡片疊層顯示。

## 技術選型

- 客戶端：uni-app（Vue 3 + Vite）。同一套頁面編譯為微信小程序和 iOS／Android App 資源；另有 H5 預覽。技術能力見 [uni-app 官方 CLI 文檔](https://uniapp.dcloud.net.cn/quickstart-cli.html)。
- 管理端：Vue 3 + Vite，瀏覽器使用。
- API：Node.js 24 內建 HTTP + SQLite。這是可直接運行的本機首版。正式多機部署需遷移至受管資料庫、HTTPS、備份、日誌與監控。

## 已實作

- 客戶端：登入、車輛及牌證查看、驗車安排、120 天內已核對牌證到期提示、十類服務要求提交、案件進度和官方來源。120 天是產品提醒設定，**不是政府統一辦理窗口**。
- 管理端：客戶開戶、車輛登記、牌證及有效期台帳、牌證核對、案件受理、分地區節點、驗車任務、進度紀錄、官方來源索引。
- 批文卡：固定卡面比例、標誌、底紋、字段標籤和警示文字參照提供的曲坤批文卡，以 SVG/CSS 程式化重繪；欄位位置由正反面模板固定，內容從資料庫生成。前端不使用批文卡底圖圖片。這是 CRM 內的模擬預覽，不提供官方文件導出或替代原件核驗。
- API：客戶資料隔離、管理員權限、密碼雜湊、登入會話、案件階段校驗；粵港／粵澳新申請、續期、換車及換司機有獨立節點。未記錄廣東批文完成時，不能把新申請的港／澳牌證節點設為辦理中或已完成；所有節點完成或標記不適用後才可關閉案件。
- 其他業務（口岸變更、持有人資料變更、補領、驗車、備案及其他要求）可以受理並分節點跟進；具體適用條件需由專員依案件類型與官方原文核實。

## 本機啟動

需 Node.js 24+ 和 npm。分三個終端執行：

```bash
cd /Users/vincentw/development/cross-border-plate-crm/api
DEMO_SEED=1 npm start
```

```bash
cd /Users/vincentw/development/cross-border-plate-crm/admin
npm install
npm run dev
```

```bash
cd /Users/vincentw/development/cross-border-plate-crm/mobile
npm install
npm run dev:h5
```

管理端本機地址 `http://localhost:5174`，客戶 H5 預覽 `http://localhost:5173`，API `http://localhost:4100`。演示資料只在新資料庫且 `DEMO_SEED=1` 時建立：管理員帳號 `admin / AdminDemo123!`；客戶端仍以電郵 `customer@demo.local / CustomerDemo123!` 登入。演示資料與密碼絕不可用於真實客戶。

正式環境不要啟用演示種子。設好 `DB_PATH`、`PORT`、`CORS_ORIGINS` 後，以環境變數 `ADMIN_USERNAME`、`ADMIN_NAME`、`ADMIN_PASSWORD` 執行 `npm run create-admin` 建立第一個管理員；帳號為 3–32 位、以英文字母開頭，可使用英文字母、數字、點、底線或連字號，密碼至少 8 字元。既有管理員升級時會自動取得原電郵 `@` 前的帳號名稱，遇到重名加序號，原密碼仍可使用。客戶端電郵登入與現有密碼規則不變。

## 編譯

```bash
cd /Users/vincentw/development/cross-border-plate-crm/admin && npm run build
cd /Users/vincentw/development/cross-border-plate-crm/mobile && npm run build:mp-weixin
cd /Users/vincentw/development/cross-border-plate-crm/mobile && npm run build:app-plus
```

小程序產物在 `mobile/dist/build/mp-weixin`，App 資源在 `mobile/dist/build/app`。發布前須填寫 `mobile/src/manifest.json` 的微信 AppID 和 App 識別配置，將 `VITE_API_BASE_URL` 指向可訪問的 HTTPS API，並完成微信平台與 iOS／Android 的簽名、審核。此倉庫沒有官方政務系統 API 接入，也不會代客戶自動向政府提交申請。

## 資料和規則邊界

業務文字與流程依 [`official-sources.md`](official-sources.md) 所列的政府／主管部門原文。官網沒有提供足以統一判定全部車牌類型的規則時，系統顯示人工核實，不自動斷定資格。辦理中、已完成等是本公司的代辦工作狀態；官方結果須在取得回執或牌證後由專員核對更新。現階段沒有文件上傳、報價支付、電子簽署、訊息推送及自動政務遞交；因此不能投入真實敏感證件資料運營。
