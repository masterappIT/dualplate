# UI 品質檢查與設計依據

檢查日期：2026-10-15。本次是針對客戶端與管理端的重新設計及實際畫面驗收。業務規則仍只以 [`official-sources.md`](official-sources.md) 的政府／主管部門資料為依據；以下設計參考只用於資訊架構與可用性，不用作業務規則。

## 參考與取捨

- [Ant Design 官方佈局規範](https://ant.design/docs/spec/layout/?locale=en-US)：以一致間距、明確區塊與自適應網格組織後台資訊。
- [Ant Design 官方資料展示規範](https://ant.design/docs/spec/data-display/)：高頻、結構化案件採可掃讀的列表／表格；低頻說明縮成輔助區塊。
- [Ant Design 官方導航規範](https://ant.design/docs/spec/navigation/)：管理端使用常駐側欄，讓案件、客戶、車輛與來源維持清楚入口。
- [HubSpot 官方 CRM 產品頁](https://www.hubspot.com/products/crm/contact-management)：參考客戶檔案、活動和待辦聚合成工作區的產品模式。

最終畫面採自有深綠與暖中性色、粵港澳跨境車務內容和專屬排版，沒有直接複製參考站頁面。

## 改版前發現

| 面向 | 實際問題 | 本次修正 |
|---|---|---|
| 排版與留白 | 管理端四張同等 KPI 卡及三張通用提示占用首屏；客戶端大裝飾卡片壓縮關鍵內容 | 管理端先顯示今日焦點、案件隊列和牌證提醒；客戶端以緊湊概覽、兩項快捷操作和最近案件呈現 |
| 視覺層級 | 主行動、次要說明、紀錄狀態混在相近權重 | 標題、數值、階段、日期和來源分層；新要求、辦理中、完成等狀態以受控色彩區分 |
| 色彩 | 卡片、背景、提醒都落在相近綠色區間 | 深綠作重點區，白色作工作表面，琥珀只表示到期／待受理，灰色表示完成／次要內容 |
| 動效與微交互 | 原畫面大多只有通用 hover | 可點擊 KPI、隊列、牌證條目與快捷入口；輸入聚焦、按鈕按下及減少動效設定均有樣式 |
| 響應式 | 管理端窄屏為兩列大卡堆疊，資訊密度差；客戶端深頁樣式不一致 | 管理端 1200／800／600／450px 斷點重排，桌面工作區限制最大閱讀寬度並提高列表字級；客戶端表單、車輛、案件詳情及登入頁統一元件系統 |
| 原創性 | 以一般 CRM 卡片拼接為主，跨境業務特徵弱 | 以「工作隊列、兩地牌證、官方依據、驗車安排」構成專屬界面結構，保留自有品牌字標 |

## 實測結果

- 管理端：在實際瀏覽器檢查工作總覽的 1280px 桌面與 390px 窄屏；390px 時 `document.documentElement.scrollWidth` 與視窗同為 390px。登入後切換案件列表，打開案件詳情，確認來源、狀態欄位與辦理節點顯示。
- 客戶端：檢查首頁、要求表單、車輛與牌證、案件詳情的渲染及導航。登入後能從最近案件進入詳情；六個示範辦理節點和官方來源顯示完整。要求表單保留新申請、粵港／粵澳及車輛選擇功能。
- 編譯：管理端 `npm run build`，客戶端 `npm run build:h5`、`npm run build:mp-weixin`、`npm run build:app-plus` 全部通過。
- 牌證提醒只使用狀態為「已核對」的有效期資料；120 天是產品提醒視窗，並非政府辦理期限。

## 待真機與上線前驗收

微信開發者工具及 iOS／Android 真機的導航、安全區、鍵盤和觸控回饋尚未實測；現階段只有編譯驗證。正式上線還需 AppID、簽名與 HTTPS API，並以真實車輛類型對照各主管部門原文核實條件。此視覺檢查不等於完整無障礙合規測試。
