管理者 2026-10-16 授權負責人代為決定，目標：**第一個可完整運作的版本**，管理者測試後再提意見。最高原則：**用戶能夠簡單使用**。

## 一、V1 要跑通的閉環

```
建檔 → 到期推算 → 今日工作派事 → 工單辦理 → 客戶看到進度與結果
  ↑                                              ↓
  └── 出租收租、收費代墊、報帳追蹤 → 每月客戶報告 ──┘
```

1. **建檔**：新客戶 → 套用委託範本 → CSV 匯入牌照或逐個新增 → 上傳批文卡自動辨識
2. **提醒**：系統按規則推算到期；我們負責的進今日工作，客戶自理的只提醒客戶
3. **辦理**：今日工作一鍵開工單 → 按業務範本出步驟清單 → 指派員工、截止日 → 缺文件時「待客戶提供」，客戶在手機上傳 → 完成後到期日自動更新
4. **客戶**：手機看牌照、公司、到期、進度；一鍵申請辦理；上傳文件；收到通知
5. **錢**：出租合約自動產生應收租金 → 記收款 → 代收的扣抽成結算給客戶；年費、每單代辦費、規費代墊記帳
6. **報帳**：內地公司每月報帳報稅工作自動產生，跟進外包會計和回執
7. **月報**：每月自動產生客戶報告（做了甚麼、到期甚麼、租金、收費、應付／應收淨額），客戶在手機查看

| 客戶自理項目 | 仍計算和顯示到期日，但不計入今日工作數字 | 辦牌時仍要用到這些公司文件；只是不派工 |
| 顧問沒有設定時怎樣顯示 | 首頁不顯示顧問卡；「我的」頁顯示「顧問資料整理中」 | 首頁放空卡片只佔位置、沒有可做的事；「我的」是客戶找聯絡方式的地方，需要交代 |
| 同一工單有多個要客戶提供資料的步驟 | 每個步驟各通知一次（按步驟去重） | 原先按「工單＋狀態」去重，第二個客戶步驟不會通知，客戶會漏交 |
| 客戶看到的狀態字眼 | 工單列表、牌照詳情的辦理記錄、更新紀錄一律轉成客戶用語（已收到／辦理中／需要你提供資料） | 驗收截圖發現「我的」頁顯示內部字眼「待客戶提供」 |
| 本公司自有牌照出租時的「出租方」 | 沿用 `lessor_type=client`（牌主本人），畫面顯示「本公司（自有）」；不另設類型 | 自有客戶本身就是牌主；`agent`（代理）只用於客戶的牌照，避免多一個意思重疊的選項 |
| 生產準備的操作記錄 | 記錄所有成功的修改請求（誰、何時、甚麼對象、送出的欄位，敏感欄位遮蔽、IP），不逐欄記前後值 | 一處統一記錄不會漏寫入點；前後值可由同一對象前後兩筆記錄比對，V1 先求不漏 |
| 200 個牌照的速度 | 實測主要接口 ≤ 22 ms，不改寫 N+1 | 遠低於 300 ms 目標；過早優化增加風險 |
| 司機證件未填日期 | 只在司機列表顯示「待錄入」，不計入今日工作；填了日期後照常提醒 | 真實資料演練：遷移出 5 位司機後今日工作多了 15 項待錄入，大部分司機不會三種證件都有，會淹沒真正要做的事 |
| 新工單的預設截止日 | 範本步驟沒有設定天數時，預設 14 天 | 實測發現新工單截止日等於今天，一建立就顯示到期 |

## 四、「簡單使用」設計準則（每份任務說明都要求遵守）

參照成熟的物業管理、車隊管理、會計事務所管理系統的共同做法：

1. **一頁一件事**：每頁頂部只有一個主要按鈕
2. **今天要做甚麼最先看到**：後台首頁是今日工作；客戶端首頁是「需要你處理的事」
3. **能在列表上做完，就不跳頁**：填日期、標記完成、開工單都在列表行內
4. **少填欄位**：新增時只要求必填項，其餘有預設值或之後補；能從批文卡、公司註冊處自動帶出的不讓人手填
5. **白話**：不用技術詞（「規則」「參數」「節點」）；狀態用顏色加文字（紅：已逾期，橙：快到期，綠：正常，灰：客戶自理）
6. **不出錯的保護**：刪除、轉讓、結算要確認並說明後果；可撤回的操作給「撤回」
7. **手機優先（客戶端）**：大按鈕、一隻手可操作；文件上傳可直接拍照
8. **空白頁要教人下一步**：沒有資料時顯示「新增第一個牌照」之類的引導

## 五、參照的成熟系統及採用做法

每份任務說明須註明參照哪一項，Codex 照此設計，不自創流程。

| 我們的模組 | 參照系統 | 採用的做法 |
|---|---|---|
| 到期提醒、90 天過關 | **Fleetio**（車隊管理）[續期提醒](https://help.fleetio.com/en_US/vehicle-renewal-reminders) | 每個到期事項有「到期日＋提前提醒天數」兩段狀態（快到期／逾期）；可批量設定或用試算表匯入；司機證件掛在司機資料上提醒 |
| 工單、業務步驟範本、定期工作 | **TaxDome / Karbon**（會計事務所管理）[比較](https://assembly.com/blog/taxdome-vs-karbon)、[Karbon](https://karbonhq.com/en-GB/solution/tax/) | 每種業務一條「流水線」，工單按階段移動（看板）；定期工作（每月報帳、每年年審）按排程自動產生；向客戶要文件時發「客戶待辦清單」，客戶上傳後自動推進，未完成自動催 |
| 客戶端 | **TaxDome 客戶入口**、**AppFolio / Buildium 業主入口**（物業管理）[比較](https://www.doorloop.com/blog/appfolio-vs-buildium) | 客戶入口只做四件事：看待辦（要你提供甚麼）、上傳文件、看進度、看報表；業主入口看月結單和文件 |
| 出租、收租、代收結算 | **AppFolio / Buildium** | 租約→每期自動產生應收；收款入帳；逾期提醒；代收的按月出**業主結算單**（租金－抽成－代墊＝應付業主）；承租方入口看帳單、上傳付款憑證 |
| 收費、代墊、月報 | **AppFolio 業主月結單**＋**TaxDome 帳單** | 月報＝業主月結單：本月收入、扣費、代墊、應付淨額，附本月完成工作和即將到期事項 |
| 今日工作、客戶一頁看全 | **HubSpot**（客戶管理）、**Karbon 工作總覽** | 首頁只列「今天要我做的」；客戶頁把公司、牌照、工單、往來集中一處 |

## 八、實用驗收：真的幫到人，才算可以生產（管理者 2026-10-16：「不是跑起來就算，我要能生產」）

- 負責人以**現有正式資料庫的本機副本**（`api/data/app.sqlite` 複製到暫存位置，不提交、不給 Codex）升級到新版本，確認：資料完整、批文卡卡面與原件完好、到期日正確、沒有遺失或錯配
